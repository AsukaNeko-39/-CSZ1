# 按改动选择验证

验证当前需求的实际行为；下面是选择清单，不是每次全部执行的固定流程。

## 文字和局部样式

- 查看受影响页面与一个窄屏布局；检查正文仍在、图名没有溢出、按钮可操作。
- 删除重复标语时，检查欢迎页中只剩正文那一次出现。
- 不为单行可逆文案变化新增只匹配文字的永久测试。代码变动按需做类型检查，准备发布时构建。

## 首页图栏/背景

- 代表宽度：1920、1440、1366、1024、768、390px；只有涉及响应式图栏时才覆盖全组。
- 检查土地制度三张、文物四张图片：同组尺寸一致、图像贴边、图名不重叠、主体可辨。
- 查看方鼎耳足、单衣领口和下摆、皿方罍顶盖和底座；完整原图入口正常。
- 首页每个缩略图打开对应详情；手机横滑到末栏后仍有田野背景。
- 详细页滚到页尾，确认背景、页尾探索入口没有丢失；仅测首屏不能证明背景完整。

## 导航/分享

已有回归测试：

```powershell
node node_modules/vitest/vitest.mjs run client/src/lib/navigation.test.ts --environment node
```

浏览器检查外部新打开根地址、`#cover` 和旧栏目后缀均先到欢迎页；进入地图后切换专题、前进后退与刷新仍恢复当前页面。地图印章返回欢迎页。顶部分享复制干净的欢迎页地址；复制权限受限时手动复制窗口可用且不超出窄屏。

使用新的浏览器会话区分代码问题与旧 HTML/旧标签缓存；先检查实际加载的 JS 文件。仅用新的查询参数测试成功，不足以证明旧缓存已被清除。给用户的入口应明确带 `#cover`。

## 分页/长图

- 翻遍受影响阶段的每一页，拼合正文后与资料原文一致；不能丢字、重复文字或遗漏最后一页。
- 字体加载后与窗口改变后仍能分页；同一视口的阶段卡片保持等大。
- 渐进放大看中间态、最终 2.8 倍、移开还原、四边与四角；点击高清窗、键盘和手机点击仍可用。
- 只在改动鼠标交互/性能时做采样；没有性能改动就不重复长时间基准测试。高速移动应合帧，避免逐事件测量布局。

## 数据与发布

资料变更按本次涉及的表格行、字段和图片比对，不把“历史已核对 50 个详情”等描述当作本次完成的证据。内容数量从实际数据取得。

发布后核对匿名访问、资源子路径、欢迎页和受影响流程。若更新 PDF，比对本地与上传文件的字节/哈希并确认公开链接可读。类型检查/构建通过只证明对应检查完成，不等于微信真机或全部功能均已验证。
