## 构建与发布核对

从实际项目目录执行，把输出放在独立目录：

```powershell
node node_modules/typescript/bin/tsc --noEmit
node node_modules/vite/bin/vite.js build --base '/-CSZ1-pages/' --outDir '<独立发布目录>'
```

核对 `index.html` 中的脚本/样式前缀与图片路径。将确认过的构建输出复制到用户公开发布仓库；保留 `.git`、已有修改记录、README 中的链接、禁索引设置、空的 `.nojekyll` 和 `404.html`。`404.html` 使用同版入口。避免删除仍可能被缓存 HTML 引用的旧哈希资源；清理旧资源是单独的维护决定。

发布前看实际 `git status`、差异和远端；仅提交本次文件，不使用通配提交混入其他改动，不强推。先处理已知错误；网络结果不确定时先读取远端提交和发布状态，再决定是否重试，避免重复发布。

发布完成后确认 Pages 状态成功，匿名读取入口和受影响资源，与本次构建比较。不能把“推送成功”当作“公开网页已经更新”。浏览器中旧查询 URL 可能有缓存；用新会话核对，并提供本次欢迎页入口。遇到登录/权限/内容冲突而无法安全继续时，说明具体阻碍，不持续盲目重试。
